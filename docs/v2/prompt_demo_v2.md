## 決定事項（本人確定）
- 差別化：「送信前に、根拠つきの答えが出る」。ポジション：SMB起点→大企業へ。価格3段（Starter 9,800／Pro 29,800／Enterprise 年額要見積、いずれも価格仮説）。電話は模擬通話が既定＋マイクは既定オフのおまけ。

## 追加・変更する機能
1. **ナビに「チャネル」を追加**し、その中に2つのタブ：「チャット（顧客側）」「電話（模擬通話）」。受信箱の各行にチャネルのアイコン（メール/フォーム/チャット/電話。線のSVG）を付ける。受信箱上部にフィルタ（すべて/AI解決/承認待ち/要確認）。
2. **チャット（顧客側ウィジェット）**：左にTaskNestのヘルプページ（架空、料金ページ風）、右下にチャットウィジェット（モバイル幅のパネル）。
   - 入力中の即答：`compositionend` 後と、IME未使用時はinputイベント（120msデバウンス）でローカル索引を検索。承認済みナレッジに十分一致（スコアしきい値）したときだけ、送信前に「3行の回答＋根拠チップ」を入力欄の上に表示（フェードイン180ms、着地音）。右上に小さく「ローカル検索 ○ms（この端末で実測）」— performance.now()で測った実際の値を表示し、直近20回の中央値も出す。
   - 一致しない・曖昧（短すぎる入力）・矛盾がある（請求書払い）質問では回答を出さず、送信すると「担当者に確認してご連絡します（デモ例）」と表示し、受信箱の要確認に要約付きで追加。
   - サンプル質問のチップ（「追加料金はいつ？」「CSVで一括登録できる？」「請求書払いはできる？」）。クリックで1文字ずつ自動入力（タイピング音つき）してデモできる。
   - 「送信後のAI生成による回答は将来機能」と小さく注記。
3. **電話（模擬通話）**：画面中央にスマホ風の着信UI（「ブラウザ上の模擬通話」と明記、架空番号）。
   - 「サンプル通話を再生」：台本（顧客「ユーザーを追加したら、いつから料金がかかりますか？」→ AI回答の音声）。発話はテキストで字幕表示しながら speechSynthesis（lang ja-JP、端末にあるローカル音声を優先、localService=true のものを探す。なければ字幕のみで進行）で読み上げ。右に通話のリアルタイム文字起こしと、参照中の根拠チップ。
   - 2本目「請求書払いはできますか？」→ AIは答えず「担当者から折り返します（デモ例）」→ 受信箱に通話要約（質問の要約・確認済み資料・確認先）付きで追加。担当者が同じ説明を繰り返し聞かなくて済むことを示す。
   - 「マイクで話す（実験・既定オフ）」トグル：ONにすると注意文「Chromeの音声認識を使います。音声はブラウザ提供元で処理される場合があります。料金はかかりません」を表示し、webkitSpeechRecognition（ja-JP）で認識→同じ索引で回答。非対応やエラー時は静かに無効化して理由を表示。
   - 電話の秒数・待ち時間の保証表現は出さない。
4. **インサイト**：チャネル別件数（メール/フォーム/チャット/電話）の小さな棒、AI解決/承認待ち/要確認の内訳を追加。効果測定の数字には「架空データによる計測例」と表示。追記候補は「14件を根拠に追記案→人が承認」まで（承認ボタンで承認済み表示）。
5. **ナレッジのループ**：要確認から「確定した回答をナレッジに追加」すると、チャットウィジェットでも同じ質問に即答できるようになる（同じ索引を共有）。これをデモで見せられること。
6. **デモガイド更新**：4ステップ「1 チャットで即答 → 2 電話（模擬） → 3 要確認を人へ → 4 追記候補を承認」。→キーで次のステップの画面に移り、自動デモ（チップの自動入力やサンプル通話再生）も実行。?step=1..4 で該当画面から開始（サンプルの問い合わせは取り込み済み状態）。
7. 品質：v1と同じデザイントークン・モーション。最小文字14px。1440×900とembed=1（1440×900固定キャンバスの縮小）で崩れない。prefers-reduced-motion対応。

完了後、構文確認と、主要な関数の動作確認（索引検索・しきい値・矛盾時に出さないこと）をJavaScriptCore等で行い、変更点と既知の制約を短く報告。
