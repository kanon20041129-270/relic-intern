## 狙い
0フォロワーのTikTokで、BtoBなのに最後まで見てしまう動画。**淡々と音と映像が進み、すべての拍で小さな「気持ちいい変化」が起きる**（satisfying UI / ASMR）。音の心地よさが最優先。ナレーションなし。文字は大きく少なく、無音でも意味が通る。最後と最初がつながるループ。

## 形式とパラメータ
- `?cut=15` / `?cut=30`（既定30）、`?format=vertical|horizontal`。v1の `t=`, `embed=1`, `autoplay`, `muted`, `safe=1`, 操作UI、キーボード操作は維持。embed時のポスター表示も維持。
- 縦はTikTok用：重要要素は x=120〜960, y=240〜1260 に収める。横はスライド用。
- **書き出し用API（必須）**：`window.AnswerLoopVideo = { duration, fps:30, width, height, ready: Promise, renderFrame(t) /* 指定時刻を同期的に描画 */, renderAudio(sampleRate=48000) /* Promise<AudioBuffer> を OfflineAudioContext で生成。リアルタイム再生と同じキューと音色 */, audioWavBase64(sampleRate=48000) /* Promise<string> 16bit PCM ステレオWAVのbase64 */ }`。`?export=1` のとき操作UI・ポスター・カーソル以外のデバッグ表示を出さず、自動再生もしない。`renderFrame` はフォント読み込み完了後に呼ばれる前提。
- 音の生成コードは「キュー配列（時刻・種類・パラメータ）→ 任意のBaseAudioContextに合成」の1つの関数にまとめ、リアルタイム再生とOfflineAudioContextの両方で同じ関数を使う。

## 音のデザイン（最重要）
- 120BPM、4/4（1拍0.5秒、2秒で1小節）。全イベントは拍グリッド（1/2拍・1/4拍含む）に乗せる。
- BGM：温かい低音のパルス（サイン＋わずかな倍音、ハーフタイムのキック感）、柔らかいパッド（ローパス、ゆっくりした開閉）、ごく小さなハイハット（ハイパスしたノイズ、ベロシティに揺らぎ）。コード進行は Fmaj7 – Em7 – Dm7 – Cmaj7 のような明るく落ち着いたもの。サビのような盛り上がりではなく、淡々と、しかし小節ごとに1要素ずつ足されて気持ちよく積み上がる。
- 効果音（すべて合成）：①柔らかいクリック（ローパスしたノイズ＋低中域の胴鳴り、40–70ms）②タイピング（音程と強さに±の揺らぎ、1文字ごと、等間隔ではなく人間らしく）③ポップ（サイン 320→160Hz、約100ms）④根拠チップの「カチッ」着地（短い木質音＋高域の小さなきらめき）⑤承認チャイム（2音上昇、メジャー3度、柔らかいベル）⑥要確認の乾いた2打＋0.5秒の完全な無音⑦スワイプ/ホワイシュ（バンドパスしたノイズのスイープ）⑧数字カウントのティック（音程が少しずつ上がる）⑨ラストのシグネチャー（ロゴで、パッドの解決和音＋ベル）。
- 効果音の瞬間はBGMをサイドチェイン風に2–3dB下げる。全体はスマホのスピーカーで聞こえる中域を残す（低音だけにしない）。マスターにコンプとリミッター、ピークは-1dBFS以下、平均はおおよそ-14 LUFS相当を目標。高域の刺さり・クリップノイズなし。
- ループ：最後の0.5秒は休符にして残響を収め、最初の0.5秒の着地音につながる。

## 映像のルール
- すべての動きは拍に着地（着地フレーム＝音の立ち上がり）。入場は cubic-bezier(0.05,0.7,0.1,1)。オーバーシュートは小さく（scale 1.02→1）。
- カメラはUIに寄る（scale 1→1.12、拍で小さくパン）。カーソルはベジェ移動、クリックで縮む＋波紋。
- 色・UIは docs/SPEC.md のトークンとデモと同じ見た目（TaskNestの架空データ。「デモ用の架空データ」を小さく常時表示）。紫グラデーション・光る効果・絵文字なし。

## 15秒版（TikTok初投稿「あるある1操作」）
0.0 フック大文字「その料金質問、また来た。」＋同じ件名のメールカードが拍ごとに3枚落ちて重なる（クリック×3）。
2.0 カードが1つの束に吸い込まれ「14件」（ポップ）。
3.0 ヘルプのチャット欄。「追加料金はいつ…」とタイピング（タイピング音）。
5.0 送信する前に、3行の答えがすっと出る（ポップ）。見出し「送信前に、もう答えてる。」
6.5 根拠チップ K1・K3・K2 が拍ごとに着地（カチッ×3）。
8.5 担当者側：同じ回答案に「承認」クリック→承認チャイム→「送信済み」。
10.5 束の14件 → 料金ページへの追記案が緑の差分で伸びる（スワイプ）。
12.5 ロゴ＋「問い合わせを、返すものから、減らすものへ。」＋CTA「プロフィールから試す」。
14.5 冒頭のフレームへ戻る位置に要素を戻し、休符。

## 30秒版（3ステップ）
research/tiktok.md 6節のキューシートを土台に：0–2 フック／2–8 送信前の即答＋根拠3つ＋承認／8–15 要確認（矛盾の2枚、0.5秒の無音、要約付きで人へ）／15–19 電話（模擬通話のUI、波形、同じ根拠で即答）／19–25 頻出→追記案→人が承認／25–29.5 ロゴ・タグライン・CTA／29.5–30 冒頭へ戻る。

完了後、構文確認、t=各秒でのrenderFrameが決定的であること、renderAudioのピークが-1dBFS以下であることをJavaScriptCore等で可能な範囲で確認し、シーン表と既知の制約を報告。
