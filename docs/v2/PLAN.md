制約：課金ゼロ（有料API・有料素材なし）。外部通信なしで動く（音声認識だけ例外としてオプション）。プロトタイプとして見せる。

## 0. v1からの変更の要約（ピッチで話す用）
1. **差別化の主軸を「速さ」に**：送信を待たせず、入力中に根拠付きの3行回答を出す（FB「送信後に待たされるのが最大の弱点」）。
2. **窓口を電話まで広げる**：メール・フォーム・チャット・電話を1つの受信箱で。電話はその場で音声回答、答えられないものは要約付きで人へ（FB・Fin/IVRy/チャネルトークの動向）。
3. **初期顧客はSMBのまま、売り方の上にエンタープライズを足す**：SMBで回答精度と改善ループを実証→同じ仕組みを大企業の窓口に接続して年額契約（FB「売り方を変えると桁が変わる」）。※要判断
4. **競合との位置づけ**：Tayori（AI付き月11,980円）・Re:lation（月15,000円〜）より安く始められ、Fin（$0.99/解決）のような改善提案を日本語の兼務担当者向けに。空白は「入力中の根拠付き即答」と「料金・仕様ページの改稿→同種問い合わせの減少まで追う」。

## 2. プロダクト改善（デモ v2）
既存のデモを壊さず拡張。追加する画面と機能：
1. **顧客側ウィジェット（新）**：TaskNestのヘルプ画面右下のチャット。入力1文字ごとに承認済み回答を検索し、3行の回答＋根拠チップを即表示。右上に「応答 0.04秒」の実測（performance.now）。送信すると確定。該当なし/矛盾は「担当者に確認します。目安 2時間以内・担当：佐藤」と表示し受信箱に要約付きで入る。
2. **電話（新）**：電話の着信UI（架空の番号）。①「話す」ボタンでブラウザの音声認識（Chromeの webkitSpeechRecognition、日本語）②対応していない/オフライン時は「サンプル通話を再生」（台本の質問をテキストで流し込む）。回答は speechSynthesis で読み上げ（端末のローカル音声）。発話終了→回答開始の時間を表示。答えられない質問は「担当者から折り返します」→受信箱に通話要約。
3. **受信箱（改）**：チャネルのアイコン（メール/フォーム/チャット/電話）。AI解決済み・承認待ち・要確認のタブ。
4. **インサイト（改）**：チャネル別の件数、平均応答時間（チャット0.04秒、電話0.6秒など、デモ値と明記）、追記候補→承認→効果測定。
5. **ナレッジ（据え置き）**：人が確定した回答がナレッジに戻る＝ループ。
6. 発表用ガイドのステップを 1即答（ウィジェット）→2電話→3要確認→4追記候補 に更新。→キーで進む。

速さの演出に嘘を入れない：比較対象として他社の秒数は出さない。「送信を待たない」体験そのものを見せる。

## 4. TikTok（0フォロワーから）
講座の4原則を採用：①伸びている近い投稿を真似る ②文言だけ変えて毎日出せる型 ③最後に宣伝 ④まず無料で需要を見る。
- **シリーズの型「問い合わせ、0.04秒。」**：毎回、実際に来そうな質問1つ → 入力中に3行の答えが即出る → 根拠チップがカチッと着地 → 承認音。質問の文言だけ差し替えて量産できる（講座②）。
- **メイン動画（30秒・縦）**：淡々と音と映像が進むASMR/satisfying型。120BPM、効果音が拍に同期（クリック・タイピング・ポップ・着地）、矛盾の場面だけ0.5秒の無音。最後のフレームが最初につながるループ。ナレーションなし、文字は大きく少なく。最後にロゴ＋プロフィールのリンク/QRへの誘導（講座③）。
- **ショート版（15秒）**：あるある1本（「その料金質問、また来た。」→即答→14件が1つの束に）。
- 横版（1920×1080）はスライド用に同じ素材で作る。
- **書き出し**：無料で実ファイル（MP4）を作る。headless Chromeで1フレームずつ撮影（30fps）＋ OfflineAudioContextで音をWAVに書き出し → macOS標準のAVFoundation（Swift）で合成してMP4。追加インストールなし。
- **素材**：音はすべてWeb Audioで合成（著作権の心配なし）。UIは自作のHTML。フォントはローカル（Hiragino/Inter）。外部素材は使わない。
- **レビュー**：①Codexが絵コンテとキューシートをレビュー ②書き出したフレームの抜き出しを私とCodexで相互レビュー ③音のレベル（ピーク・ラウドネス）を数値で確認 → 直してから完成。
- 投稿文・ハッシュタグ・最初の10本の企画は research/tiktok.md の表をベースに docs/v2/tiktok_plan.md に。

## 7. Codexレビュー（13:05）の反映 ※この節が1〜6節より優先
1. 速さの見せ方：「0.04秒」をシリーズ名・KPIから外す。メッセージは「送信前に、根拠つきの答えが出る」。数字を出すときは「ローカル検索 ○ms（この端末で実測・中央値）」と測定対象を明記。
2. 即答の安全策：IMEの変換確定後に検索し、承認済み回答に十分一致したときだけ表示。矛盾・曖昧・対象外は出さず、送信後に要確認へ。送信後のAI生成は「将来機能」と明記。
3. 電話：既定は「ブラウザ上の模擬通話」（台本＋端末の読み上げ。課金・通信なし）。回答できる1件と、要約付きで人へ渡す1件。マイク認識は既定オフの実験機能（Chromeの音声認識は無料だが音声が外部で処理されうる）。電話の秒数や「2時間以内」は出さず、担当・待ち時間は「デモ例」と表示。
4. MP4書き出し：Swift＋Chrome DevTools Protocolで `render(n/30)` を撮影、OfflineAudioContextで48kHz WAV、AVAssetWriterでH.264＋AAC。まず2秒の試作で同期を確認してから全尺。
5. 4分の進行：横動画は15秒だけ流す。SNSは静止画＋計画で説明。目安：課題・対象45秒／製品・動画30秒／デモ60秒／競合・事業40秒／SNS・FB・締め50秒／予備15秒。
6. 競合：ポジションマップではなく比較表（入力中の提示・根拠表示・改稿後の計測）で「確認できた／未確認」を明記。Tayoriが遅いはFBによる検証仮説。Finは「成果あたり$0.99」。
7. 価格：「競合より安い」は言わない。Pro・Enterpriseの金額は価格仮説と明記。音声原価は総額未試算。月24,000円相当はStarterの仮定。
8. 大企業：買い手＝既存コールセンター/CSの責任者。料金・契約の定型電話1窓口で試験導入し、解決率・応答時間・再問い合わせで評価。権限・監査履歴・データ保持・SLA・音声基盤の提携は導入条件。
9. 改善ループの到達点：デモは「14件を根拠に追記案→人が承認」まで。効果の数字は「架空データによる計測例」と表示。
10. TikTok：国内の近い投稿3〜5本を型の参考に記録（冒頭1秒の言葉・最初の動き・最後の見せ場）。初投稿は14〜16秒の1操作。差し替え用テンプレート（質問・回答・根拠）。週2〜3本で10本検証。
11. CTA：最後に製品名とCTAを1つ。リンク欄が使えなければコメント誘導（「よく来るのは料金と仕様、どちら？」）。自社宣伝の開示設定をオン。24時間・7日で冒頭維持率・平均視聴秒数・業務コメント・デモ希望を記録。
