あなたはトップクラスのプロダクトデザイナー兼フロントエンドエンジニアです。
docs/SPEC.md を必ず最初に読み、その内容（プロダクト・デザインシステム・架空データ）に厳密に従って、
`demo/index.html`（必要なら demo/app.js, demo/style.css）に AnswerLoop のプロダクトデモを実装してください。
docs/ 以外のフォルダ（video/, slides/）は触らないこと。外部CDN・ネットワーク通信・有料APIは使わない（AIの動作は決定的なルールでシミュレーション）。

## 目的
発表中に40秒でライブデモする。Linear / Intercom / Front のような、静かで上質なSaaSのUI品質を目指す。1920×1080の投影でも、ノートPC(1440×900)でも崩れない。スマホ幅では縦積み。

## 画面構成
- 上部ヘッダー：ロゴ「AnswerLoop」、ワークスペース名「TaskNest」、小さく「デモ用の架空データ」、右側にKPI 3つ（SPEC参照）。KPIは操作に応じてカウントアップ（tabular-nums）。
- 左ナビ：受信箱（件数）／要確認（件数・オレンジ）／インサイト／ナレッジ。
- 受信箱：中央に問い合わせリスト（ジャンルのタグ、送信者、件名、状態バッジ：回答案あり=青、要確認=オレンジ、送信済み=緑）、右に詳細ペイン。
- 初期状態は空の受信箱＋「問い合わせCSVを取り込む」ボタン（サンプルCSVを読み込む。ファイル選択でCSV[列: 送信者,件名,本文]も受け付ける）。取り込むとリストが1件ずつ流れ込み（stagger 60ms）、各行で「根拠を検索中」のスケルトン→状態バッジへ変わる（合計1.5秒程度）。
- 詳細ペイン（回答案あり）：問い合わせ本文 → AI回答案（AI生成であることを明記）。本文中の根拠チップ [K1] などにホバー/クリックすると、下の「根拠」リストの該当資料の該当文がハイライトされる。信頼度表示。ボタン：「承認して送信」(主)、「編集」、「人に回す」。承認すると送信アニメーション→緑の「送信済み」＋トースト「送信しました｜対応時間 1分12秒」、KPI更新。
- 詳細ペイン（要確認）：オレンジの帯で「AIは回答しません：資料間で記載が食い違っています」。K4とK5を左右に並べて差分を強調。「担当者への引き継ぎメモ」（質問の要約、確認済みの資料、確認すべき人）。ボタン「担当者に割り当て」「確定した回答をナレッジに追加」→ 追加すると ナレッジに新しい項目が増え、「次回から自動で回答案を作れます」と表示（＝ループ）。
- インサイト：頻出質問の横棒ランキング（アニメで伸びる）。その右に「追記候補」カード：料金ページに「ユーザーを追加したときの料金」節を追加。差分プレビュー（追加文を緑ハイライト）。「根拠の問い合わせ 14件を見る」で一覧を開く。「ページ改善後の効果測定」：閲覧1,000回あたり 4.2件 → 目標 2.0件。
- ナレッジ：K1〜K6の一覧（出典の種類・最終確認日・状態：確定/要確認）。

## 発表用の工夫
- 右下に小さな「デモガイド」：1 回答案を承認 → 2 要確認を確認 → 3 追記候補を見る。現在のステップが進むとチェック。キーボード：→ で次のステップへ自動遷移（クリックしなくても進められる）、R でリセット。
- URLに ?step=1..3 で該当画面から開始できる。
- 操作音：小さく上品なクリック・送信音を Web Audio API で合成（音量控えめ、ヘッダーにミュート切替。初期はON、最初のユーザー操作でAudioContextを開始）。

## 品質
- モーションは SPEC の値（200–300ms、emphasized decelerate）。prefers-reduced-motion で抑制。
- フォーカスリング、ボタンの押下状態、ホバー状態を丁寧に。コントラストはWCAG AA。
- 完成後、`node` は無いので、HTMLの構文と JS のエラーが無いことを目視で再確認し、最後に実装した機能の一覧と既知の制約を短く報告してください。
