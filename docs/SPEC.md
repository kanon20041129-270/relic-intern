# AnswerLoop（仮称）｜共通仕様書（Codex実装用）

Relic 1dayインターン（2026-11-28）の発表用。デモ・プロモ動画（横/縦）・スライドの3つを作る。
すべて **静的HTML/CSS/バニラJS**。ビルド不要、外部CDN・外部API・ネットワーク通信なしで動くこと（会場Wi-Fiが落ちても動く）。
Google Fontsの読み込みは可だが、失敗しても Hiragino Sans / system-ui で崩れないこと。
フォルダ構成（このフォルダがそのまま Vercel の静的サイトになる）:

```

  demo/index.html     … プロダクトデモ
  video/index.html    … プロモ動画（?format=horizontal|vertical）
  slides/index.html   … 発表スライド（動画とデモを中に埋め込む）
  docs/               … 仕様・台本（編集しない）
```

## 1. プロダクト概要（全成果物で表現を統一）

- 名前：**AnswerLoop**（アンサーループ、仮称）。タグライン：**「問い合わせを、返すものから、減らすものへ。」**
- 対象：自社SaaSをリリースした従業員数十名のスタートアップ。問い合わせを兼務する事業担当者（利用者）と事業責任者（購入者）。
- 何をするか（3ステップ。どこでもこの順・この言葉で）
  1. **根拠付きの回答案**：既存FAQ・仕様資料から回答案を作り、根拠の箇所を必ず示す。担当者は確認して承認するだけ。
  2. **要確認は人へ**：根拠が足りない／資料同士が矛盾する質問はAIが答えず「要確認」として人に回す（理由と経緯の要約つき）。
  3. **FAQ改善ループ**：同じ質問の頻度を集計し、料金ページ・FAQへの追記候補を出す。人が答えた内容は確定したらナレッジに戻る。
- 差別化の一言：「返信を速くするだけでなく、同じ問い合わせそのものを減らす」「既存のメール窓口のまま使える」「AIが勝手に送らない（人の承認）」。
- 原体験（数字はこの表現でのみ使う）：開発者がBaseconnectの長期インターンで問い合わせ対応を担当し、ナレッジ約80件を整備。**本人の問い合わせ対応時間：1日約8時間 → 15分未満（本人の概算）**。
- 価格：**30日間の有償トライアル 19,800円**／**継続 月額9,800円／社**。個別のFAQ整理・カテゴリ追加は有償オプション。
- 価値の試算：月60件 × 1件8分短縮 ＝ 月8時間 ＝ 時給3,000円換算で **月24,000円相当**（仮定）。

## 2. デザインシステム（全成果物共通）

世の中で良いとされる原則（出典つき・確認日2026-11-28）を反映する：
- 1画面1メッセージ・大きく太い文字・強いコントラスト・3秒で分かる（YC "How to Design a Better Pitch Deck"、Duarte "The Glance Test"）。
- モーション：入場はdecelerate系 `cubic-bezier(0.05, 0.7, 0.1, 1)`（Material 3 Emphasized Decelerate）、通常 200–300ms、大きな場面転換 400–600ms。動きは意味のある変化（状態の変化・注目の誘導）にだけ使う。
- AIサポートUX：AIであることを明示、根拠を見せる、人への引き継ぎでは経緯・理由の要約を渡して顧客に同じ説明をさせない、ユーザーが常に主導権を持つ（承認ボタン）。
- 縦動画：1080×1920。重要な文字・UIは上240px・下660px・左右120pxを避けた中央に置く（TikTok公式の広告セーフゾーンの数値。保守的に採用）。最初の1秒でフックの文字を出す。

トークン（CSS変数で定義）:
```
--ink:#0B1220; --ink-2:#344054; --muted:#667085; --line:#E4E7EC;
--bg:#F5F6F8; --surface:#FFFFFF; --navy:#0E1A33;
--accent:#2E5BFF;        /* 主役の色。1画面で一番見てほしい1か所に */
--accent-soft:#E8EDFF;
--ok:#12B76A; --ok-soft:#E7F8EF;     /* 承認・送信済み */
--warn:#F59E0B; --warn-soft:#FFF4E0; /* 要確認 */
```
- 書体：`"Inter","Noto Sans JP","Hiragino Sans",system-ui,sans-serif`。数字は Inter の tabular-nums、太さ800。見出し 800–900。
- 角丸 12–16px、影は1段だけ（`0 1px 2px rgba(16,24,40,.06), 0 8px 24px rgba(16,24,40,.08)`）。
- **使わない**：紫系グラデーション、光る効果、絵文字、アイコンの羅列、「革新的」「シームレス」などの空の言葉。アイコンは必要最小限のインラインSVG（線1.75px）。
- ロゴ：角丸の正方形の中に、ループ（円弧の矢印）と吹き出しを組み合わせたシンプルなインラインSVG＋ワードマーク「AnswerLoop」。

## 3. 架空データ（全成果物で同じ内容を使う）

架空の会社：**TaskNest（タスク管理SaaS・従業員30名）**。画面上に小さく「デモ用の架空データ」と表示。
問い合わせのジャンル（Baseconnectで実際に使った分類）：**お金回り／プロダクト仕様／会員情報／不具合／その他**。

ナレッジ（根拠）:
- K1 料金ページ「プランと料金」：「Proプランは月額1,200円/ユーザー。月の途中でユーザーを追加した場合、追加日から月末までを日割りで次回請求に加算します。」
- K2 利用規約 第8条：「請求は毎月1日に確定し、追加ユーザー分は翌月請求に含めます。」
- K3 FAQ「ユーザーの追加方法」：「設定 → メンバー → 招待。招待したユーザーが参加した時点で課金対象になります。」
- K4 料金ページ「お支払い方法」：「クレジットカード・請求書払いに対応。」
- K5 社内仕様メモ（2026-11）：「請求書払いはデザイン・実装中。提供開始は未定。」 ← K4と矛盾
- K6 FAQ「タスクの一括インポート」：「CSV（UTF-8）で最大5,000件まで一括取り込み可能。」

問い合わせ（受信箱、8件程度。主要3件）:
1. 【お金回り】「追加料金はいつ発生しますか？」（株式会社ミナト 佐藤さん）→ 回答案あり、根拠 K1・K3・K2、信頼度 高。
   回答案：「お問い合わせありがとうございます。ユーザーを追加した場合、招待したユーザーが参加した時点で課金対象となり[K3]、追加日から月末までの日割り料金を次回のご請求に加算いたします[K1][K2]。」
2. 【お金回り】「請求書払いはできますか？」（合同会社ノース 田中さん）→ **要確認**。理由：「料金ページ（K4）と社内仕様メモ（K5）で記載が食い違っています。確定情報がないため、AIは回答しません。」担当者への引き継ぎメモ（質問の要約・確認済みの資料・確認すべき人：経理/プロダクト担当）。
3. 【プロダクト仕様】「CSVで一括登録できますか？」→ 回答案あり、根拠 K6。
4〜8. 「ユーザー追加の料金」「日割り計算」「請求書払い」系の類似質問を混ぜ、頻出集計で「料金・ユーザー追加」が最多になるようにする。
