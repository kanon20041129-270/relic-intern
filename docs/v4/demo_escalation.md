## 元にする実際の運用（開発者がBaseconnectで作ったフロー）
1. 有人対応になった新しい問い合わせを自動で読み込み、「ナレッジ追加の候補」にする。
2. 規定（社内ルール）に沿って、ヘルプセンターに追加すべきか自動で判定する（例：同種が2件以上／料金・契約・仕様に関わる／個別事情ではない）。
3. 必要な情報を自動で調査・整理する（料金ページ・規約・社内仕様メモ・過去の返信を突き合わせる）。
4. 情報が取れない・食い違って確定できないものは、人が判断する（担当者に確認依頼）。
5. 確定した情報から「回答例」と「ヘルプ記事の本文」を自動で作り、ナレッジに記録＋ヘルプセンター記事に掲載＋AIの回答ソースに取り込む。
6. 次から同じ質問はAIが即答する（チャット・電話の索引も更新）。

## 実装
- 要確認の詳細画面（請求書払い）で、担当者が「回答して送信」（例文：「請求書払いは現在準備中です。提供開始が決まり次第ご案内します。」）を押すと、右側に「ナレッジ自動更新」パネルが開き、上の1〜6が順にチェックされていくタイムライン（各0.5秒、操作音つき）。4は「確認先：経理／プロダクト担当 → 確定済み」と表示。5で回答例と記事本文のプレビュー、6で「チャット・電話の索引を更新しました」。
- その後チャット（顧客側）で「請求書払いはできる？」と入れると、送信前に新しい承認済み回答が出る（既存のループ機能を使う）。
- デモガイドに5番目「人の回答→ナレッジ自動更新」を追加し、?step=5 で開始可能に。→キーで自動実行。
- ナレッジ画面に「更新履歴」（いつ・何の問い合わせから・誰が確定）を表示。
- 表記は「デモ用の架空データ」「ヘルプセンター掲載（デモ）」とし、実際の外部送信はしない。
完了後、変更点を3行で報告。
